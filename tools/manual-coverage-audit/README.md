# FF14 汉化与中文搜索审计 V1.3.4（浏览器实测版）

Mirapri Eden 已支持：在首页、装备排行榜或制作器中采集。导出保留各页面的 hash 路由身份，去除搜索参数；玩家标题、署名、正文归为用户内容。本站截图和 Canvas 内的文字不属于 DOM 汉化扫描范围。

适用于 `jdysw/ff14-glamour-zh` 的九站（十个域名）审计。**它是本地只读审计工具，不会上传数据、自动导航、登录、提交表单、拦截或改写请求，也不绕过反爬验证。**

## 文件和安装

- `FF14-Coverage-Audit-V1.1.user.js`：直接在 Tampermonkey 中更新现有安装，避免同时启用多份审计脚本；正式汉化脚本可保持开启。
- `audit-core.js` + `search-diagnostics.js` + `audit-runtime.js`：油猴脚本的可审查源码；`node build-userscript.mjs` 可重新生成安装文件。
- `generate-report.mjs`：离线生成摘要、去重候选 CSV 和 Markdown，读取当前 zhx-manual-audit-v2 格式的 JSON。

## 基本操作

1. 在 Tampermonkey 安装新 `.user.js`，关闭**旧版审计脚本**，但不要关闭正式汉化脚本。
2. 浏览站点首页、筛选页、装备页、详情页等。右下角选择“汉化后 / 残留扫描”，点击“采集当前页面／状态”。
3. 在同一 URL 展开菜单、弹窗、切换筛选后再次采集。脚本将按当前页面状态指纹保存不同快照；如果两种状态自动识别不到区别，可以填写“交互状态标签”（例如 `菜单展开`）。
4. 在“扫描轮次”输入 `PR27-before`、`PR27-after` 等稳定名称，使同一页面的不同版本快照互不覆盖。**用户手动填的轮次只用于数据归档，并不自动识别正式脚本版本**。
5. 打开页面后自动采集是可选功能，等待 DOM 沉静一段时间（最长约 15 秒）；不会假定等候完成就代表汉化完全就绪。重要页面建议手动复采。
6. 导出 JSON：默认删除玩家作品和未核实的装备名，并不输出周边文章 `parentText`；若为分析误报明确需要原始玩家内容，可主动勾选“导出玩家内容 / 物品名”。**请检查文件是否包含作者信息或隐私内容后再分享。**

## 新增：中文搜索链路诊断（V1.2，需手动开启）

用于排查 EC `/gearsets` 的**中文输入后候选不出现、候选点击无效、检索始终为空**等问题；也可诊断其他受支持站点的装备搜索框。此功能**默认关闭**，原有汉化覆盖扫描仍可独立使用。

1. 正式汉化脚本保持开启；将本审计脚本更新到 **1.3.4**。安装文件名称沿用 `FF14-Coverage-Audit-V1.1.user.js`，保持现有安装的更新地址与油猴身份，不要同时启用两个审计版本。
2. 打开 `https://ffxiv.eorzeacollection.com/gearsets`，在审计面板点 **「开始搜索诊断」**。开关会保存在当前设备的油猴本地存储，允许跨页面跳转持续记录，直到手动停止。
3. 输入「幻境」「御敌」等套装词，尝试候选点击、回车、搜索按钮；搜索前后均可点 **「记录搜索状态」**，记录输入框、候选和套装链接数量。
4. 复现后点 **「停止搜索诊断」→「导出 JSON」**，把 `ff14-audit-v1.3-*.json` 提供给开发者。即使没有汉化快照，也能单独导出搜索诊断记录。
5. **「清空记录」** 会删除汉化快照及搜索诊断事件，请先备份。

新导出的 JSON 在顶层追加 `searchAudit`，旧有 `baselines` / `pages` 字段和报告逻辑不变。最多保留 **3 次会话、每次 360 条事件**。

**记录内容：** 搜索框识别信息、有限长度的搜索词样本、中文输入、输入法合成事件、候选数量与前 4 项中文/原生名、焦点/回车/提交/候选选择、URL 搜索参数、套装链接数以及同源搜索请求的路径、耗时、可见响应状态码。全部记录在本地，**不发起额外网络请求**。

**隐私与技术边界：** 不采集密码、账号/作者/玩家字段、其他无关输入框、请求或响应正文、Cookie、Authorization；搜索词仍可能含敏感信息，分享 JSON 前应复核。`PerformanceObserver` 不拦截网络流量，只能观测浏览器向脚本暴露的资源，状态码可能为空；`searchBoundVisible=false` 也不能证明正式脚本未启动。工具不覆写 fetch/XHR、不会修改搜索行为，观测到的候选与链接数量不等于服务器已经返回了有效结果。

## 如何获得基线

### A. 自动变化见证（默认、无需关闭正式脚本）

脚本在 `document-start` 安装观察器，能够记下其启动**之后**发生的部分文本节点和属性值修改的旧值，标记 `matchQuality = inferred-old-value` 与 `baselineQuality = partial-inferred`。

**限制**：Tampermonkey 脚本运行顺序不受此工具控制；网站的同步更新可能替换整个节点；旧值可能是动态中间态而非翻译前原文。因此这种数据只用于辅助定位，**不能当成完整原文基线或用于计算完整覆盖率**。

### B. 人工核验原文基线（需要两次刷新）

1. 在 Tampermonkey 暂时关闭**正式汉化脚本**，保持当前审计脚本开启，刷新页面。
2. 面板选择“原文基线 / 关闭正式汉化”，保持相同 URL、筛选条件和“交互状态标签”，采集。
3. 重新开启正式汉化脚本、面板切回“翻译后 / 残留扫描”，刷新相同页面，重新采集。
4. JSON 中 `hasBaseline=true`、`baselineQuality=manual-verified`；逐项 `before` 仍可能因动态重排而匹配失败，`matched/ambiguous` 字段反映这一点。只有有明确匹配的节点才能用于前后对比。

人工基线在轮次间共享，但要求 URL、状态指纹与状态标签一致。同一 URL 不能随意改变筛选后还要求匹配。

## 离线审计和版本对比

安装 Node.js 22+，在工具包目录运行：

```powershell
node .\generate-report.mjs "C:\Users\你\Downloads\ff14-audit-v1.3-xxx.json"
```

指定输出目录并与旧版本导出比较：

```powershell
node .\generate-report.mjs "C:\path\new.json" ".\reports" --compare "C:\path\old.json"
```

输出：`ff14-审计报告.md`、`ff14-去重候选.csv`、`ff14-审计汇总.json`，使用 `--compare` 时另有 `ff14-版本差异.json`。

- `suspected-no-baseline`：**只有外文残留**，没有原文对照；不是已确认漏译。
- `suspected-untranslated`、`suspected-partial`：结构匹配的节点翻译前后仍含可检测外文，需复核实际含义。
- `excluded-user`、`item-review`、`metadata-review`、`needs-review`：玩家内容、装备名、浏览器标题或不确定区域，**不直接计入确认漏译**。
- 同一 URL + 状态指纹 + DOM 键 + 文本用于版本 diff；元素移动、消失或筛选状态变化可能造成“已解决”假象，应结合页面状态复核。

## 数据兼容与安全边界

- 只读取当前 zhx-manual-audit-v2 格式及当前本地记录；V1 格式和 V1 存储迁移已移除。现有 V2 记录保持可读。
- 不采集网页中用户输入的文本框、密码输入或可编辑区域，也不会抓取账号/API 等敏感路径。完整的站点公开页面文本仍可能包含真实名字、作品信息，故导出时默认脱敏。
- 只采集当前浏览器实际访问的内容。**不等于全站遍历**，也不能证明剩余页面 100% 已汉化。
- DOM 位置并非永远稳定，具有 ID、测试标识、链接目标的元素优先使用稳定锚点；其他元素退回结构定位并可能需要人工复核。

### 1.3.2 审计修正

站名和版权等精确固定文本标为 `exempt-ui`，保留原文且不计为已翻译；FAQ、关于、徽章收藏页的固定说明不再误判为玩家内容。公告、普通玩家文字及未知区域仍需分别复核，不能将豁免或无基线记录作为完整汉化率。

1.3.2 另修正统计页中链接至标签筛选的普通标签分类，保留并按玩家内容处理；按钮的 `value="on"` 等内部提交值不作为可见文案采集，按钮正文及输入式按钮的显示值仍会采集。

### 1.3.3 历史适配清理

移除 V1 格式和 V1 本地存储迁移；导入／报表读取只接受当前 V2 格式。安装标识保持不变，正常更新已有安装即可。
