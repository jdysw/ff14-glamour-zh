# FF14 汉化覆盖审计 V1.1.1（浏览器实测版）

适用于 `jdysw/ff14-glamour-zh` 的七站（八个域名）审计。**它是只读的本地采集工具，不会上传数据、自动导航、登录、提交表单，也不绕过反爬验证。**

## 文件和安装

- `FF14-Coverage-Audit-V1.1.user.js`：直接在 Tampermonkey 中安装。请停用或删除旧版 V1.0 审计脚本，避免重复采集；正式汉化脚本可保持开启。
- `audit-core.js` + `audit-runtime.js`：油猴脚本的可审查源码；`node build-userscript.mjs` 可重新生成安装文件。
- `generate-report.mjs`：离线生成摘要、去重候选 CSV 和 Markdown，支持 V1.0 和 V1.1 的 JSON。
- `test-core.cjs` / `test-browser.py`：分别验证分类、基线配对、兼容性和 Chromium 模拟 DOM。

## 基本操作

1. 在 Tampermonkey 安装新 `.user.js`，关闭**旧版审计脚本**，但不要关闭正式汉化脚本。
2. 浏览站点首页、筛选页、装备页、详情页等。右下角选择“汉化后 / 残留扫描”，点击“采集当前页面／状态”。
3. 在同一 URL 展开菜单、弹窗、切换筛选后再次采集。脚本将按当前页面状态指纹保存不同快照；如果两种状态自动识别不到区别，可以填写“交互状态标签”（例如 `菜单展开`）。
4. 在“扫描轮次”输入 `PR27-before`、`PR27-after` 等稳定名称，使同一页面的不同版本快照互不覆盖。**用户手动填的轮次只用于数据归档，并不自动识别正式脚本版本**。
5. 打开页面后自动采集是可选功能，等待 DOM 沉静一段时间（最长约 15 秒）；不会假定等候完成就代表汉化完全就绪。重要页面建议手动复采。
6. 导出 JSON：默认删除玩家作品和未核实的装备名，并不输出周边文章 `parentText`；若为分析误报明确需要原始玩家内容，可主动勾选“导出玩家内容 / 物品名”。**请检查文件是否包含作者信息或隐私内容后再分享。**

## 如何获得基线

### A. 自动变化见证（默认、无需关闭正式脚本）

脚本在 `document-start` 安装观察器，能够记下其启动**之后**发生的部分文本节点和属性值修改的旧值，标记 `matchQuality = inferred-old-value` 与 `baselineQuality = partial-inferred`。

**限制**：Tampermonkey 脚本运行顺序不受此工具控制；网站的同步更新可能替换整个节点；旧值可能是动态中间态而非翻译前原文。因此这种数据只用于辅助定位，**不能当成完整原文基线或用于计算完整覆盖率**。

### B. 人工核验原文基线（需要两次刷新）

1. 在 Tampermonkey 暂时关闭**正式汉化脚本**，保持 V1.1 审计脚本开启，刷新页面。
2. 面板选择“原文基线 / 关闭正式汉化”，保持相同 URL、筛选条件和“交互状态标签”，采集。
3. 重新开启正式汉化脚本、面板切回“翻译后 / 残留扫描”，刷新相同页面，重新采集。
4. JSON 中 `hasBaseline=true`、`baselineQuality=manual-verified`；逐项 `before` 仍可能因动态重排而匹配失败，`matched/ambiguous` 字段反映这一点。只有有明确匹配的节点才能用于前后对比。

人工基线在轮次间共享，但要求 URL、状态指纹与状态标签一致。同一 URL 不能随意改变筛选后还要求匹配。

## 离线审计和版本对比

安装 Node.js 22+，在工具包目录运行：

```powershell
node .\generate-report.mjs "C:\Users\你\Downloads\ff14-audit-v1.1-xxx.json"
```

指定输出目录并与旧版本导出比较：

```powershell
node .\generate-report.mjs "C:\path\new.json" ".\reports" --compare "C:\path\old.json"
```

输出：`ff14-审计报告-v1.1.md`、`ff14-去重候选-v1.1.csv`、`ff14-审计汇总-v1.1.json`，使用 `--compare` 时另有 `ff14-版本差异-v1.1.json`。

- `suspected-no-baseline`：**只有外文残留**，没有原文对照；不是已确认漏译。
- `suspected-untranslated`、`suspected-partial`：结构匹配的节点翻译前后仍含可检测外文，需复核实际含义。
- `excluded-user`、`item-review`、`metadata-review`、`needs-review`：玩家内容、装备名、浏览器标题或不确定区域，**不直接计入确认漏译**。
- 同一 URL + 状态指纹 + DOM 键 + 文本用于版本 diff；元素移动、消失或筛选状态变化可能造成“已解决”假象，应结合页面状态复核。

## 数据兼容与安全边界

- 可读取 V1.0 的 `zhx-manual-audit-v1` 导出，也能从 Tampermonkey 旧版存储迁移。迁移不提升原有数据的基线可信度；旧数据依靠 `ctx`/DOM 路径重新分类。
- V1.1 格式为 `zhx-manual-audit-v2`，不会自动写回 V1.0 格式。升级前建议先导出 V1.0 备份。
- 不采集网页中用户输入的文本框、密码输入或可编辑区域，也不会抓取账号/API 等敏感路径。完整的站点公开页面文本仍可能包含真实名字、作品信息，故导出时默认脱敏。
- 只采集当前浏览器实际访问的内容。**不等于全站遍历**，也不能证明剩余页面 100% 已汉化。
- DOM 位置并非永远稳定，具有 ID、测试标识、链接目标的元素优先使用稳定锚点；其他元素退回结构定位并可能需要人工复核。

## 实测回归（2026-10-09）

使用三份 V1.0 真实审计文件（EC 14 页、EndCloset 6 页、Mirapri 9 页）验证兼容迁移和分类器：共 8,234 条旧记录，归并 307 条重复下拉选项记录；Mirapri 玩家自拟作品标题从错误 UI 判定转为用户内容。此结果**仅验证规则和离线分类表现**，不代表新版在全部真实站点上的复扫已经完成。
