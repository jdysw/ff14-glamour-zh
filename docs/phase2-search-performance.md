# 第二阶段：搜索性能与 EC 分类快照优化

## 发布原则

本阶段基于第一阶段已合并代码开展，保持用户脚本版本号 **1.4.4**，不创建 Release，也不触发数据部署。所有新增或修改的注释使用中文。

## 中文部分词倒排

原实现每次查询都对全部中文正式名称与别名做 `includes`，时间复杂度随全站候选数线性增长。现将相邻两个 UTF-16 码元作为索引键，按需建立倒排桶；对较长查询选取最小的候选桶后，再按完整查询字符串做 `includes` 校验。

倒排列表仍按原 `localeCompare` 排序，因此保留原有正式名优先、前缀高于包含、部位分组高于匹配度、别名排序与最终数量限制的行为。索引只为当前站点加载的数据建立，刷新后按新一代数据重建。

回归测试以至少 4000 条合成名称逐项对比全量扫描结果，并验证稀有词显著缩小实际检查范围。候选数下降不等同于在所有设备上已经实测提速。

## EC 官方分类常量压缩

四类饰品和鸟甲原生名依然内置在用户脚本里，**不依赖网络下载**。生成器将排序后相邻名称按「36 进制共同前缀长度 + 后缀」编码；运行时还原并构建原有 `Set`。面饰保持中英文对照。

| 指标 | 优化前 | 优化后 |
|---|---:|---:|
| 自动生成的分类区段字符数 | 158,803 | 86,692 |
| 分类区段减少 | — | 45.4% |
| 四类饰品名称数量 | 5,105 | 5,105 |
| 鸟甲 / 面饰数量 | 104 / 61 | 104 / 61 |

上述数字是**源码区段字符数**，不是 gzip 后的网络传输量。测试以旧快照每类完整数据的独立 64 位指纹保护名称、顺序和官方分类，并验证 Python 生成器产物的逐字节可复现性。

## 上游数据源固定版本

Cloudflare 数据部署读取的权威 `Item.csv` 由浮动 `@master` 改为固定提交 `d9582a624eaec69d45649366dee801c2f3a6e9b3`（xivapi/ffxiv-datamining）。更新上游数据需单独审查后明确修改 SHA。本 PR 不改 canonical TSV、也不主动部署数据站。
