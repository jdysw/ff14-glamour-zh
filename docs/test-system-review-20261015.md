# 测试体系审查（2026-10-15）

## 发现的问题

1. 旧测试自行复制正则，生产正则写坏也可能继续通过；版本、模块、治理测试则主要检查源码拼写、注释和历史文件名。
2. core/cache/storage/site-registry 与 native 测试重复，前者还需要大量按源码标记切片和重新装配。
3. Miramiru 把整批译文另存为期待表，与词典逐条比对，无法独立说明译文是否正确。同一批筛选值又在 Node 和浏览器重复核对。
4. 独立搜索的三份脚本重复初始化、生成数据和等待。测试安装包还重跑完整三语／React 回归。
5. CI 用子串选测试，把部分单元测试额外选进集成 job；同名离线／在线测试也可能一起执行。
6. 主测试工作流各 job 重建同一份脚本，构建契约 job 内又重复重建。未上线的 V3.1 和报告工具也混入日常回归。

## 删并决定

| 原内容 | 处理及保留的保障 |
| --- | --- |
| 两份复制正则测试 | 删除；生产翻译函数和页面行为继续验证输出 |
| module-source / version-consistency / quality-governance / architecture | 删除重复源码哨兵；正式构建继续执行版本、模块及依赖检查；保留依赖验证器自身的正反例 |
| core / cache / storage / site-registry | 删除重复装配；native 直接执行生产模块，补入存储拒绝、旧 API 删除降级、启动异常等独立场景 |
| build-idempotent / dict-single-source | 合成 build/test-pipeline，验证重建不漂移、篡改拒绝、再生恢复，不核对源码注释 |
| Ronka / Collection 独立搜索 + 四站提交 | 合成六行矩阵；保留输入不自动搜索、候选选择、原生事件、未知名称、表单对照、回车和按钮提交 |
| Miramiru 两份整表译文副本 | 删除副本和循环，保留少量规则、官方／普通标签边界、数量格式和实际 DOM 操作 |
| Miramiru 筛选枚举副本 | 缩到九个跨类别控件和两个官方标签，继续检查三语渲染、职业提示、原始 ID 和普通标签保护 |
| Miramiru 独立安装 | 只验证内置数据和真实存储隔离；完整三语／React 行为只跑一次 |
| 真站零候选断言脚本 | 删除与覆盖审计工具的重复；保留实际点击筛选、详情和静态页面的真站检查 |
| V3.1、存储审计、基准报告工具 | 移到 experimental 显式执行；数据基线工作流更新路径并继续验收原型 |

原默认 62 个脚本不包含 native 的七个文件；调整后默认 52 个脚本已经包含它们。这是执行文件数，不是断言或业务场景数量。

## CI 与选择器

主测试流水线的重复构建收口到一个 build job，再做一次可重现验收；其余任务共享同一 userscript 工件。移除单独的 Contracts job。Wiki／Sites 按套件精确分组，unit 和 native 各执行一次。

外站覆盖审计改为手动触发，403 在报告和手动工作流中仍然失败。不存在的测试名失败；同名离线／在线文件必须指定路径，防止意外联网。runner 记录每个文件耗时，不设“必须多少测试”的数量目标。

## 验证

- 完整离线入口：52/52 通过，本机一轮约 197 秒；此前同机约 229 秒。负载会影响耗时，不将该数字作为固定门槛。
- 构建／实验分层：4/4 通过；独立搜索矩阵六个行为场景约 9 秒。
- 在独立临时目录中对真实源码做三次变异：去掉域名边界、把存储失败报告为成功、接受 HTTP 503。未修改副本先通过，三个错误副本均被保留的断言检出；该临时检查不增加日常测试负担。
- 业务代码、词典和版本未改动。

部分提取源码的历史测试仍覆盖独有故障或复杂输入，暂时保留。本次没有为减少文件数而删除独有失败场景，也没有用 import 包装旧脚本伪装合并。
