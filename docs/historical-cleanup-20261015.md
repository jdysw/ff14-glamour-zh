# 历史适配与冗余接口审查

## 已清理

| 范围 | 结论与处理 |
| --- | --- |
| `dictGet` / `dictHas` | 仅测试调用的包装。生产直接读取词典对象；删除包装后保留实际词典合并、隔离、回滚的行为测试 |
| `dataGetTable` / `storeSet` | 无生产调用的数据访问器、无等待写入包装，删除 |
| Ronka 缓存转发导出 | 无消费者，缓存仍由核心模块直接拥有，删除站点的转发导出 |
| `observeLocal` | 只有 `createObserver` 的参数包装。当前调用点改用工厂，保持各自 300／400 ms 的防抖和异常边界 |
| `itemDbReady` | 单纯包装数据 Promise 与回调。调用点直接等待 `ensureTables`，保留回调异常隔离 |
| `DATA_REMOTE=true` | 已无第二种运行模式，删除恒真开关与对应条件分支 |
| 模块迁移历史哨兵 | 删除只检查已退役工具名称的 `verify-module-source` 及 npm 命令；实际依赖检查、编译、语法、模块顺序和产物验证继续执行 |
| `build/migrate` | 唯一剩余脚本其实是当前构建顺序验证器，迁至 `build/verify-build-order.mjs`，更新根目录计算及调用点 |
| 审计 V1 JSON／本地存储迁移 | 旧格式导入和旧存储读取链删除，当前 V2 格式保持可读；审计工具为 1.3.3 |
| 报告中的旧版命名 | CLI 导出使用 `coverage-audit-live-manual.json`，报告文件取消固定 v1.1 后缀；安装标识保持现有值，已有当前安装可正常更新 |

`normalizeItems` 原名含 Legacy，但它仍负责当前 CLI 采集结果的分类、重复 option 合并与隐私归属判断，因此保留功能并更正命名。

## 保留与后续候选

- 同步／异步 GM API、无枚举 API 时的安全缓存处理，是当前脚本管理器支持；不是旧脚本版本分发。
- Unicode 码元处理、物品别名和首条记录优先属于当前查询语义，不能根据“兼容／历史”注释直接删除。
- V3.1 原型仅在 experimental 执行，其中 V3 指当前格式来源，不是旧客户端读路径。
- `resolveAllByName` 当前仅测试消费，关联现行 V3 的 `dup` 文件和多译索引。七个逻辑文件合计约 13 KB。若要移除，应在数据格式精简时一起调整发布器、清单、校验和读侧；本轮没有改变已发布协议。

## 验证原则

调用关系以实际 import 和引用为依据；删除仅用于旧包装的断言，保留当前数据处理和用户行为验证。当前 V2 审计记录可生成报告，V1 格式明确报错；不通过保留虚构接口满足测试。
