# v1.5 搜索体验统一：设计与验收

## 一、目标与边界

- 在六个幻化网站的**装备搜索输入框**内，保持同样的中文输入、候选排序、键盘/触摸选择、提交与失败回退语义。
- 不新增跨站搜索服务器、不劫持全站所有文本框、不修改各站结果页或站内筛选范围；灰机 Wiki 的反查链接不属于本次搜索提交链。
- 原生语言搜索继续由原站处理；只有明确能够解析为站点原生名称的中文搜索才转换。
- 不在输入停顿时自动转换或主动搜索；只有选择候选、回车或点击原站搜索按钮才执行转换。

## 二、用户操作契约

| 场景 | 期望 |
| --- | --- |
| 中文名完整输入 | 不自动改写输入框；可查看中文/原站语言双语候选 |
| 中文包含词 | 可命中装备名中间片段、中文别名 |
| 候选排序 | 精确名称 > 正式名前缀 > 正式名包含 > 别名前缀 > 别名包含；同组稳定排序 |
| 选中候选 | 自动触发一次站内查询；表单使用 `requestSubmit()`，独立框/vue-select 派发原生名的 `input` |
| 回车（未选择候选） | 原站表单/按钮继续执行；能够解析时在提交链中转换为原生名 |
| 未命中、外文输入 | 不擅自提交不可确定的原生名；保留原站行为 |
| 输入法组合态 | 不弹候选、不转换，不拦截用于确认组合输入的 Enter |
| 移动端视口变化 | 根据 `visualViewport` 重新定位候选面板，触摸行高 44px |
| 大量候选 | 保留全部候选数据，首批渲染 80 条；滚动触底/键盘跨批按需加载 |
| 局部筛选 | 原生站点筛选参数保留，避免附加无效空值参数 |

## 三、各站覆盖矩阵

| 站点 | 搜索适配 | 不能干预 |
| --- | --- | --- |
| Mirapri | GET 表单，中文转换时保留有效筛选、清理空值参数 | 玩家、作者、标题相关输入 |
| FF14-FC | 装备部位页面原有搜索表单 | 不改变头/身/手/腿/足部分类结果范围 |
| Eorzea Collection | 套装页系列/职能映射、部位页 vue-select、普通装备搜索 | Search by title；不得把 vue-select 错当常规 form 序列化 |
| Ronka LookBook | React/独立框的原生 setter 与 input 事件 | 普通表单、无关文本输入 |
| FFXIV ARMOURY COLLECTION | 独立搜索框、日文名称转换 | 用户创建内容、非装备输入 |
| End Closet | 独立搜索框、韩文名称转换 | 一般页面输入和控制按钮 |

## 四、实现和后续维护

- `src/core/data-manager.js`：中文倒排映射，候选分组匹配与排序；保留可幻化装备、时尚配饰和鸟甲的允许名单。
- `src/core/chinese-search.js`：六站能力表、表单搜索与 SPA/v-select 提交、候选控制器和渐进渲染。
- `src/sites/eorzea-collection.js`：Eorzea Collection 套装系列/职能查询解析。
- `src/core/site-registry.js`：站点生命周期；中文搜索仍从 `src/main.js` 在站点启动前初始化。

当前保留 `chinese-search.js` 为单一物理模块，以兼容 v1.4 的 Rollup 顺序校验与源码区段测试；**并未完成 search-engine/search-controller/search-adapters/search-suggest 物理拆分**。后续如需拆分，应与模块顺序契约及基于源码片段的测试装配同时迁移，不能只移动函数。
