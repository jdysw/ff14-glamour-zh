# FF14 幻化站中文化 v1.4 重构计划书（PR #15 后更新版）

> **用途：交给代码型 AI 逐阶段执行。**
>
> 本文不是架构建议，而是实施清单。执行者必须先阅读仓库实际源码，再按阶段修改；不得把多个阶段合并成一次“大重写”。

## 0. 当前基线

本计划以 **PR #15「perf/diag: 读取路径调度 + 运行与性能探测 + wiki 注入回退加固（v1.3.1）」合并后的 `main`** 为基线，对应合并提交 `77a2328`。

PR #15 已完成的核心工作包括：

- `buildTables` 的分片让出从嵌套 `setTimeout` 改为 `MessageChannel`，并保留失败回退。
- `_ensureFinalize` 的 `requestIdleCallback` 超时兜底由 2000ms 降至 500ms。
- 增加 `?zhx_probe=1` / `#zhx_probe` 运行与性能诊断面板。
- 增加 Wiki `getSlot()` 三路回退。
- Wiki 重试由 12 次增加到 16 次，并增加更长重试窗口。
- 增加 `__zhxWikiTries` 诊断计数。
- 为 PR #15 的 Sonar 新代码问题做了第二轮清理。
- `buildTables` 已拆成 `_btNext` / `_btStep` / `_btApplyTargets`。
- 已进行 `test-probe`、`test-wiki-fallback`、`test-index-scope` 及全量回归验证。
- PR 报告的发布产物约 224 KB，且 `build.sh` 二跑幂等。

参考：
- PR #15：`https://github.com/jdysw/ff14-glamour-zh/pull/15`
- Merge commit：`https://github.com/jdysw/ff14-glamour-zh/commit/77a2328`

# Phase 6：重构 ItemIndex / ItemResolver

## 目标

这是本次 v1.4 的核心结构性重构。

当前代码仍然是：

```text
hash → 中文名
中文名 → EC_ID
外文名 → 中文名
中文名 → 韩文名
```

且名称索引仍是单值。

## 6.1 建立统一 ItemRecord

建议：

```js
{
  key,
  zh,
  en,
  ja,
  ko,
  hash,
  ecid,
  aliases,
  order
}
```

字段可根据实际代码调整。

---

## 6.2 名称索引改为支持重名

目标：

```text
唯一：
name → ItemRecord

重名：
name → ItemRecord[]
```

推荐：

```js
Map<string, ItemRecord | ItemRecord[]>
```

而不是所有结果都强制数组化。

---

## 6.3 保留历史优先顺序

必须保留：

```text
原 TSV 行顺序
```

作为最终无法消歧时的 fallback。

禁止随机选择。

---

## 6.4 Resolver 统一 API

至少：

```js
resolveByHash(hash)
resolveByEcid(ecid)
resolveByName(name, options)
resolveByAlias(alias, options)
resolve(input)
```

统一优先级：

```text
1. hash
2. EC_ID
3. 其他稳定 ID
4. 明确语言名称
5. alias
6. 普通名称
7. 历史兼容 fallback
```

但最终以现有实际行为和 golden tests 为准。

---

## 6.5 站点不再直接访问内部 Map

例如 Wiki 不应再直接：

```js

koByZh[...]
```

而应：

```js
itemResolver.resolve(...)
```


# Phase 8：统一 DOM Target Pipeline

## 目标

解决同一页面多次：

```text
querySelectorAll()
```

重复扫描的问题。

## 当前主要问题

现有逻辑仍包含：

```text
zhTargets()
zhPlainTargets()
zhCardTargets()
zhDyeTargets()
```

以及各站点自己的 scanner。

不要直接删除这些 selector。

先将它们包装成：

```js
collectTargets(root)
```

输出标准 target：

```js
{
  type,
  element,
  text,
  context
}
```

例如：

```text
item
plain-item
card
dye
attribute
wiki-slot
```

---

## 8.1 Full Scan 与 Local Scan 统一

统一：

```js
processRoot(root, context)
```

使：

```text
document.body
```

和：

```text
Mutation added subtree
```

走同一处理路径。

---

## 8.2 幂等

必须保证：

```text
第一次处理：
外文 → 中文

第二次处理：
跳过

重新处理
```

## 验收

- [ ] 重渲染结果不变。


```text

→

→
构建多个索引
```

即使现在有 `_siteIndexes()`，也仍然要读取同一大表。



```text

↓

+

+

```
