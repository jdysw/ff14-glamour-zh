## Phase 1：建立持久化测试基线 —— ✅ 完成（2026-10-06）

### 交付

- 测试资产从开发机临时目录迁入仓库 `tests/`，**零私人目录依赖、零仓外绝对路径**：
  - `unit/`：2 项纯 Node 单元测试（正则行为）
  - `integration/`：7 项离线夹具测试（wiki ×3 / index-scope / ec / probe / 构建幂等）
  - `live/`：8 项真站测试（kasuga / fc-pages / banners / ronka / acl ×2 / dict-rt / e2e）
  - `benchmark/`：1 项读取路径基准（PR #15 工具）
- 统一入口：`npm test`（= unit + integration，离线）与 `test:unit / test:integration / test:live / test:all / test:core / test:bench`
- `tests/run.mjs` runner：串行执行、单项超时（默认 320s）、日志落 `tests/.cache/logs/`、
  自动确保 headless Chrome（无实例时自动拉起、跑完关闭；9222 VNC 环境不受影响）
- 新增构建幂等自动测试（`build.sh` 二跑 sha256 一致 + `node --check dist`）
- helpers：`cdp.mjs` / `chrome.mjs` / `paths.mjs` / `dict.mjs`（dict.json 即时生成，不依赖仓外产物）
- 计划书与进度入库（`docs/`）

### 风险与遗留

- `benchmark`（bench-read-path）已迁入但未跑全档（长跑工具），待进入数据层阶段时采集基线。
- live 套件不进默认 `npm test`（依赖外网），发布前用 `test:core` / `test:live` 全跑。
- 锚点纪律：修改 `src` 分发区段 / `buildTables` / `neededTables` 等被锚定区段时，必须同步检查相关测试的锚点计数（详见 `tests/README.md`）。
