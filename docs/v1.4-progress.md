## Phase 6：重构 ItemIndex / ItemResolver —— ✅ 完成（2026-10-06）

### 目标与落法

- 计划书 Phase 6：统一物品索引解析（hash / 名称 / 重名 / 别名），站点与翻译器不再直查内部 Map。
- 落法（与 Phase 4/5 同策略）：单文件内**区段化**，向未来 `src/core/item-resolver.js` 边界对齐——
  新增 `@zhixia:core-item-resolver` 区段（**data-layer 大区段之外**、dictionary 之前）。
- **行为等价优先**：解析语义与既有查询完全一致（同名键**首行胜**）；「重名支持」以**新增注册表**实现——
  不改 `nameMap` 结构、不动既有查询结果。真实数据侦察：en / ja / ko 重名键约 200 个，其中「同键多译」
  仅 52 键（多为套装 / 部件对），其余为「同名同译」（重复行，无解析歧义）。

### 实现内容

- 统一入口（5 函数）：`resolveByHash` / `resolveByName` / `resolveAllByName` / `resolveAlias` / `resolve`；
  优先级：hash → 名称 → 历史兼容 fallback（latinFallback）→ alias（以现有实际行为为准）。
- 衍生注册表（数据就绪后构建）：重名键（同键多译）→ `_irDupMap`（52 键）；别名（alias 列以全角分号
  拆分）→ `_irAliasMap`（23 键）；同名同译的重复行不登记（不影响任何查询结果）。
- **消费点统一（13 处）**：tryEnToZh / lookupJp2Zh / ronkaItemLookup / fcLinkZhName / _fcJumpName /
  lookupZh（重构为 resolve 调用）/ EC 站 6 处（zhPlainTargets / zhCardTargets / zhApplyCards /
  zhApplyPlain / zhDyeTargets 及 …In 变体）——**裸查 nameMap / itemHash 清零**（仅余 resolver 段内部）。
- 就绪钩子：`itemDbReady(() => _irBuildAux(ITEM_DB_TEXT))`；加载早期未注册时全部查询路径安全回退（等同既有行为）。

### 坑（教训）

- **新 core 段的就绪注册会在数据层测试装配体中级联**：resolver 段尾的 `itemDbReady(...)` 注册在 test-data-layer
  装配体（含 data-layer 区段）里会真的触发 `ensureTables → _ensureFinalize`，而装配体不含探测区 `__zhxMark`
  → ReferenceError。处理：数据层测试装配体屏蔽 `itemDbReady`（`'itemDbReady = undefined;'`）；注册行为由
  test-item-resolver 专测。
- **跨段引用的补段纪律**：lookupZh / tryEnToZh 等被数据层测试提取的函数改为调用 `resolve*` 后，
  test-data-layer 装配体须**补提取 resolver 区段**——与 Phase 5 同源：**改被锚定区段前先查其测试的提取集**。
