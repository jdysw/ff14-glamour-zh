## Phase 2：冻结数据层与 Resolver 行为 —— ✅ 完成（2026-10-06）

### 交付

- 新增 `tests/unit/test-data-layer.mjs`（75 项断言，**0.7s**，零 Chrome / 零外网）：
  - **提取装置**：按锚点（`ANCHORS`）从 `dist` 提取数据层代码段，在 Node 内装配运行；
    锚缺失 / 不唯一时明确报错（结构变化的哨兵，照报错更新锚点即可）。
  - **解析层覆盖**（`_btRow` / `_btHashRow` / `_btNameRow` / `_btNamePut`）：
    正常行 / `-` 行 / 表头 / 非法列数 / 空行 / 同键首值 wins / 染剂收集。
  - **查询路径覆盖**：`lookupZh`（hash → 名称优先级）/ `tryEnToZh` / `lookupJp2Zh` /
    `lookupEcIdByZh`（Wiki 反查用）/ Ronka 两条（`ronkaKoByZh` + `ronkaItemLookup`）/
    `lookupSeries`（精确 → ・剥离 → 前缀）/ `lookupAclCfc`（ACL 副本表）。
  - **必须覆盖清单**全部落实：正常名称 / 空名称 / hash / EC ID / alias / 染剂 / 多语言 / 重复名称 / 空行 / 表头 / 非法列数 / 旧数据。
  - **数据源三级**：手写 fixture（机制级）→ 真实行（运行时从 `data/` 现取，不手抄）→ 全表程序化抽样。
  - 注入形式与运行时对齐：`series` / `acl` 按 `applyTable`（src 4248-4249）以「前导 `\n`」形式注入。
- runner 接入 `unit` 套件；`tests/README.md` 维护约定补充数据层测试说明。

### 现状记录（golden 钉住的「非直觉」行为，重构不得无意破坏）

- alias 列（p[7]）不参与任何索引（现状）；空 zh 行会写入空串键、查询侧 `|| null` 归一。
- hash 段仅匹配十六进制（`/item/([0-9a-f]+)/i`）；非 hex 段落入名称回退。
- 同键冲突一律「首行胜」（en/ja/ko、hash、ecid、ko 五处一致）。
- 负缓存：`tryEnToZh` / `ronkaItemLookup` 对缺失值缓存 null；`lookupJp2Zh` 超长（>80）不写缓存。
- `lookupAclCfc` 依赖行首 `\n` 边界（加载层补前导 `\n`，src 4248-4249）。
- `buildTables(scope)` 非全量构建会把未选索引置空（重建语义）。

### 遗留

- 系列 / 物品**前缀推导**（`_getSeriesPfx` / `_getItemPfx`，FC 站辅助）依赖链较长（`FC_ROLE_ZH` / `DICT_FC` / `_lcs90`），未纳入本阶段；
  其输入（`nameMap` / 系列表）已被冻结，如后续 Phase（如 Phase 6）触及再补测。
